# 在线歌曲开头被截断的调查

日期：2026-09-14。

## 现象与实机证据

用户在 iPad Pro 11 英寸（第 3 代）使用自带扬声器游玩 OurTaiko
Fanmade 的 MarbleBlue. 和宿星審判时，音符已出现甚至可击打，音乐却稍后
才开始，开头像被截掉。设备安装的是 Debug 构建。

从设备提取两首已下载的 `play.tja` 和 `audio.ogg`，使用相同缓存、Debug
配置、设备和 `--auto` 启动参数复现。测试在结算前结束，不提交测试成绩。
两首文件都是 48 kHz 双声道 Vorbis。FFmpeg 检测文件开头低于 -50 dB 的
静音分别约为 0.400 秒和 0.260 秒；文件本身的这段静音不能解释开局后
跳过一至两秒音频的现象。

临时计时版本的单次测量如下。这是软件解码及播放调度时间，不是触摸到
扬声器的端到端延迟，也不是所有设备或 Release 构建的性能指标。

| 歌曲 | 完整音频加载耗时 | 原逻辑晚到后跳过的音频 |
| --- | ---: | ---: |
| MarbleBlue. | 4137 ms | 1354 ms |
| 宿星審判 | 3642 ms | 2120 ms |

两次日志都确认 `start_song()` 被调用时 `song_music` 尚未就绪，但
`song_started` 已变成 true。随后 `poll_pending_song()` 收到音频，调用
`play_sound()` 后立刻 `seek_sound()` 到已运行的谱面位置，实际丢掉开头。
直接运行已缓存歌曲即可复现，因此此问题不依赖当次网络下载。

## 修复行为

继续在线程中加载完整音频。主线程每帧只检查 future 是否就绪；等待期间
不推进谱面、判定和开场转场，完成的这一帧也计入等待时间。随后走正常
开局路径，从音频第零帧播放，删除晚到后追赶进度的 seek。

复用这一异步路径的练习模式同时等待音频，并向 `start_song()` 传入谱面
相对时间，修正之前传入绝对时钟的调用。双人模式已经同步加载音频，移除
原本无工作的 future 轮询；段位模式继续使用其同步加载路径。

这属于共享游戏逻辑修改，可能影响桌面和 Android 的异步加载场景。
没有改音频队列、谱面 OFFSET、输入校准、判定窗口、下载缓存或成绩协议。
慢文件会让开场加载停留更久，之后完整播放；此改动不加速解码。
加载失败时的既有无音乐行为不在本次修复范围。

## 修复验证

相同 iPad、缓存及 Debug 配置的临时计时版通过以下实机检查：

| 场景 | 加载耗时 | 加载完成时谱面位置 | 正式播放时谱面位置 |
| --- | ---: | ---: | ---: |
| MarbleBlue. 普通模式 | 4171 ms | -1601 ms | 617 ms |
| 宿星審判普通模式 | 3616 ms | -258 ms | 742 ms |
| MarbleBlue. 练习模式 | 4107 ms | -1601 ms | 617 ms |

三次均先完成加载，再开始播放；完成加载时 `song_started=false`，正式
播放时 `song_music` 已就绪。实际解码耗时没有显著变快，但不再在加载
期间推进谱面或跳过开头音频。表中谱面位置包括原谱面 OFFSET 和预备时间，
不是已经播放的音频时长。尚需用户用在线选曲路径确认主观听感。

移除临时日志后的 iOS Debug 完整构建、应用签名校验和实机覆盖安装通过，
最终包再次确认 MarbleBlue. 正常启动播放，随后恢复普通启动供用户复测。
源码与最终可执行文件均已检查无临时诊断标记。Android、桌面、
双人及段位模式未执行本次运行回归；双人和段位的音频同步加载逻辑未变。

## 复测方法

1. 保持设备的配置、皮肤、音频路由和构建配置相同；使用缓存内的 `play.tja`
   路径和 `--auto` 直接启动，不必重复登录、下载或提交成绩。
2. 在 `init_tja()` 的异步任务中临时用 `steady_clock` 计时 `load_sound()`。
   在 `poll_pending_song()` 完成处记录谱面时间、`song_started` 和累计等待；
   在 `start_song()` 记录 `song_music.has_value()`。旧版还需记录晚到 seek
   的目标位置。不要在音频回调内逐块同步写日志。
3. 用 `devicectl device process launch --console` 或 Xcode 收集设备输出，
   验证完成加载先于开始播放，等待期间谱面不推进、没有开局追赶 seek。
4. 完成两首普通模式及练习模式复测后，移除临时计时日志，重新构建、签名、
   覆盖安装，并让用户以原在线选曲路径确认听感。保留设备 Documents。

独立 C++ 夹具使用当前 `poll_pending_song()` 方法体、可控 promise 和
虚拟帧时钟，检查慢加载、立即完成、早于初始化结束的首帧、完成帧、完成后
正常计时、空结果及无待加载任务；这些状态检查已通过。它不替代完整游戏、
其他平台或物理音频输出验证。
